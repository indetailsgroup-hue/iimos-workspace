🎯 4 การตัดสินใจสำคัญก่อนเริ่ม Build
1. ใช้ LLM Provider ใด?
แนะนำGPT-4o — Vision ดีที่สุด, Thai language ดี, API เสถียร, ราคาสมเหตุสมผล
ทางเลือกClaude 3.5 — reasoning ดีมาก, context ยาว, Vision ดี แต่ราคาสูงกว่า
2. Multi-agent vs Single Router?
แนะนำMaster Router + 28 Specialists — user ส่ง input ครั้งเดียว, router ส่งต่อ agent ที่ถูกต้องตาม SOP
ทางเลือกSingle LLM + function calling — ง่ายกว่าแต่ไม่ scale หาก agents เพิ่ม
3. Build in-house vs ใช้ Partner?
แนะนำHybrid — hire AI Engineer 1-2 คน + ใช้ SOP เป็น spec ให้ vendor พัฒนา Phase C-D
ทางเลือกFull outsource — เร็วกว่าแต่ต้องควบคุม prompt quality ด้วยตัวเอง
4. เริ่ม Deploy กี่ Agent ก่อน?
แนะนำ5 agents แรก — เลือก high-impact + เรียนรู้ pattern ก่อน scale ไป 28
ทางเลือก14 agents (Phase 1+2) — deploy ตาม phase ที่ SOP กำหนด

⚠️ Critical Path & Risks
ความเสี่ยง Phase ระดับ วิธีป้องกัน
Prompt quality ต่ำ — agent output ไม่ตรง SOP spec B HIGH ใช้ SOP S1–S58 เป็น ground truth, ทำ unit test ทุก prompt ≥85% pass
Vision accuracy ต่ำ — อ่าน drawing dimensions ผิด B–C HIGH ทดสอบ GPT-4o vs Claude Vision ด้วย drawing จริงของ DAPH ก่อน commit stack
CRM/ERP integration ล่าช้า — vendor ไม่มี API D MED ระบุ API requirement ตั้งแต่ Phase A, มี fallback (CSV import) ไว้ก่อน
User adoption ต่ำ — DAPH team ไม่ใช้ agent E–F MED ให้ team ร่วม UAT Phase E, เริ่มจาก Line OA ที่คุ้นเคย
Cost overrun — API call ราคาสูงกว่าคาด C–F LOW ตั้ง token budget per agent ใน Phase A, monitor monthly ผ่าน PGB (S58.3)
Thai language quality — LLM output ภาษาไทยไม่เป็นธรรมชาติ B LOW GPT-4o / Claude มี Thai quality ดีมาก, เพิ่ม Thai few-shot examples ใน prompts
